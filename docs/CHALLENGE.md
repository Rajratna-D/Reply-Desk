# Challenge reference

Source: https://dev.to/challenges/hacktoberfest-week2-2026-10-12 (copied and summarized on 2026-10-14; re-check the page for changes).

## Challenge

Hacktoberfest Open-Source AI Challenge: Week 2 (challenge 3 of 5), part of the HF26 DEV Challenge Hub (https://dev.to/challenges/hf26).

## Prompt (same for all five challenges)

Build something with open-source AI at its core. That can mean running an open-weight model, building on an open-source agent harness or framework, running inference locally, or all three. The open pieces should be what makes the project work.

In the post, explain why open innovation matters for what was built. Examples the organizers give: runs on a laptop with no internet, keeps someone's data off a server they do not control, lets you fine-tune or swap models or change agent behaviour, costs nothing to run. Say where the open approach worked better than a closed one.

## Week 2 theme: "Side Hustle"

Build something with open-weight models or open-source AI that someone would actually pay for. Think small, specific, useful. Solve a real problem for a real person (freelancer, small business owner, niche community). Bonus points for landing a first user: get it in front of someone, let them use it, and report how it went (did they pay, would they, what did they ask for next).

## Key dates

- Contest start: 12 Oct 2026
- Submissions due: 18 Oct 2026, 11:59 PM PDT (that is 19 Oct, about 12:29 PM IST). Target: submit by the evening of 18 Oct IST.
- Winners announced: week of 19 Oct

## Rules that affect how we build

- The project and its repository must be started and completed inside the challenge window. Commits after the deadline must be noted in the README.
- Pull requests to existing projects do not count. It must be a new project.
- One submission per challenge. Teams of up to 4 allowed (list DEV handles in the post).
- 18+ only.
- Using AI tools to help build is allowed. Credit any non-trivial prior work or open-source code used.
- Plagiarism leads to disqualification.
- Submission is a DEV post using the template: What I Built, Demo, Code, How I Built It, Why Does Open Innovation Matter?, My Agent Session (optional), My First User (optional), Prize Categories. Required tags: `devchallenge`, `hf26challenge`.
- Non-English posts are not eligible for prizes. The post itself must be in English (the app can support other languages).

## Judging criteria

1. Writing quality (weighted most heavily)
2. Relevance to the prompt and theme
3. Creativity
4. Technical execution
5. Use of partner technology (optional)

## Prizes

Overall winner: $250 + DEV++ membership + badge. Partner categories: $200 (featured) or $100 each. Every valid submission gets a completion badge. Cash winners may need to provide eligibility paperwork and tax information.

## Partner categories we may enter (only if genuinely used)

- Best Use of Gemma ($200): we run Gemma locally via Ollama. Qualifies.
- Best Use of a .tech Domain ($100): only if we claim the free domain at hacktoberfest.com/my/promos and host a demo there.
- Best Use of DigitalOcean / Render ($200): only if we really host a demo there.
- Best Use of GitHub Copilot / Entire / Sentry / others: only if genuinely used. Do not enter categories for technology that is not in the project.

## What this means for the build

- The "why open" argument must be backed by something we can show: offline operation, local data, swapping models and comparing them, cost per reply.
- The write-up carries the most weight, so record what happened as we go in `docs/BUILD_LOG.md`.
- Honesty matters. Report real results and real failures. If there is no real first user, say so.
